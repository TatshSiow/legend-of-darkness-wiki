GameItemDetailLayer::showEquipDetail (0x7a85ac):
- 0x7a9454..0x7a945a reads the encoded calculated main stat, offsets 0x98 / 0x94.
- 0x7a94cc decodes this pair; 0x7a94d6 passes that result to the main-stat text formatter.
- 0x7a965e..0x7a9668 reads the separate encoded secondary value, offsets 0x88 / 0x84.
- 0x7a96ea calls GameEquipment::getEquipExpGrowValue (0x79d5d8).
- 0x7a96f0..0x7a96fe decodes the secondary value, converts it to float, multiplies by the growth result and truncates to integer for display.
- 0x7a8966..0x7a8970 stores pointers to encoded enhancement (0xf0 / 0xf4); 0x7a99f0..0x7a99fc decodes these and compares with 11. +12 and above uses the active label color; +0 through +11 uses the locked color. Isolated instruction checks: equipment-ui-native.json.

Limits:
The wiki previews item kinds, not individual generated inventory objects.
Secondary values shown in the wiki are item subvalue baselines; equipment-experience growth is not simulated.
Generation parameters tematt/temhp/temdef are not fixed displayed affixes.
Artifact stars, enchantments, sockets and set activation depend on an individual item or loadout; no screenshot-specific instance is assumed for every copy of an item.

Additional UI rules (equipment-ui-native.json):
makeEquipParagon preserves fixed affixes and fills to five using getParagonExtraAttrNotHave. The latter samples the configured 17-type vector by random modulo length and retries types already present. Published slot rates and item inclusion rates approximate a uniform sample without replacement; they are not independent rolls.
Paragon equipment has up to three sockets. Opening the next socket consumes item 5200 (Punch), quantity = existing socket capacity + 1: 1/2/3 Punch. refreshView 0x794b3c..0x794b58 decodes capacity at gear+0x118 XOR gear+0x11c, adds one, stores the requirement and passes item 0x1450 (5200) to createPriceSpr. touchEvent 0x793efa..0x793f2e checks this item and amount, then calls changeBagGoods(5200, -requirement); 0x793f3a..0x793f7a increments capacity. This branch does not deduct magic stones.
The former 100/200/300 magic-stone amounts belong to gem insertion: refreshView 0x794e76..0x794e98 uses the occupied gem vector at gear+0x120/+0x124; touchEvent 0x79428c..0x794324 deducts money, one selected gem, and appends its record. They are not socket-opening costs.
Gem removal: refreshView 0x794d7a..0x794da0 computes ((occupied * 12 >> 2) * 0x5555555c + 20) mod 2^32, equivalent to 20*(occupied+1): 40/60/80 magic stones for 1/2/3 occupied gems. touchEvent 0x793eac..0x793ec6 checks money; 0x7940f4..0x794100 deducts it. 0x794170..0x79417c returns the selected gem with changeBagGoods(id, +1), and 0x794180..0x7941aa erases its gem record without reducing socket capacity.
